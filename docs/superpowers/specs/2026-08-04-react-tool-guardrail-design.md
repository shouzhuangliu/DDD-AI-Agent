# ReAct 工具调用防失控设计

## 目标

让每次 ReAct 工具调用都经过服务端准入、频率控制和结果反馈，避免模型随意调用工具、重复调用同一工具、调用不存在/未授权工具后继续循环。

## 核心口径

- 不把 10 次作为业务频率限制；总步数只作为最后一道安全熔断。
- 频率控制使用当前执行的滑动窗口，默认保留最近 8 次工具请求。
- 相同工具和相同参数在窗口内首次允许，第二次拦截并反馈“重复调用”。
- 同一工具在窗口内超过 4 次时拦截并反馈“调用过于频繁”，但不同参数的合法查询可以继续推进窗口。
- 不存在、未授权或不符合当前用户意图的工具调用立即拒绝，不进入真实工具执行。
- 连续两次工具失败或两次防护拦截后停止当前工具循环，避免模型继续试错。

## 数据流

1. 模型返回 ToolCall。
2. `ReActToolContext` 根据工具名、参数、绑定白名单、用户意图和滑动窗口生成准入结果。
3. 拒绝结果写入工具消息、内存工具结果和 SSE 轨迹，使用稳定的中文错误码与说明。
4. 允许结果才进入真实 callback；成功/失败结果统一持久化，供日志页按会话和 Agent 展示。
5. 达到重复/失败熔断后，向模型和用户返回明确的下一步建议，不再盲目重试。

## 防护类型

| 类型 | 判定 | 反馈 |
| --- | --- | --- |
| 未知工具 | 不在当前 callback 清单 | 未发现该工具，列出当前可用能力 |
| 未授权工具 | 不在 Agent 生效白名单 | 当前 Agent 未授权，要求重新配置绑定 |
| 意图越权 | 用户只是反馈/查询，却请求 Bash、读项目或写文件 | 当前请求未授权该高风险动作 |
| 重复调用 | 同工具+同参数在窗口内再次出现 | 已拦截重复调用，使用上一次结果 |
| 工具超频 | 同工具在窗口内超过 4 次 | 已拦截频繁调用，要求改变查询条件或补充信息 |
| 连续失败 | 连续两次工具返回错误 | 已停止工具链，请检查 MCP、参数或服务状态 |
| 总步数熔断 | 达到执行安全上限 | 已达到执行安全上限，停止继续调用 |

## 可观测性

- 每个 ToolCall 保存工具名、参数、准入结果、错误码、耗时和最终结果。
- SSE 轨迹保留 `action`、`observation`、`error/tool_guardrail`，前端可直接显示拦截原因。
- 失败结果同时进入 `MemoryToolResult`，避免后续会话重复尝试同一错误工具。

## 测试范围

- 正常调用通过。
- 窗口内相同参数第二次被拦截，窗口淘汰后可再次调用。
- 同工具不同参数在频率阈值内通过，超过阈值被拦截。
- 未知工具、未授权工具和意图越权均不执行 callback。
- 连续失败触发停止，正常调用后失败计数归零。
